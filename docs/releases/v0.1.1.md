# CodexBoard 0.1.1

CodexBoard 0.1.1 aligns runtime approvals with the current Codex app-server
policy model, so a task no longer forces every safe repeat action through an
isolated “allow once” decision.

## Highlights

- Choose between allowing once and remembering an approval for the current task.
- Remember an exact command-prefix rule when Codex proposes one.
- Remember an allow or deny rule for a specific network host when offered.
- Allow repeated file changes to the same files for the current task.
- Grant exact permissions for one turn, for the task, or for one turn while
  continuing to strictly review every command.
- Clearly distinguish “deny and continue” from “deny and stop this turn.”

CodexBoard renders only decisions supported by the active app-server request.
Persistent command and network rules appear only when Codex supplies the exact
rule payload; the application does not synthesize broader authorization.

## Install this local preview

1. Download `CodexBoard-v0.1.1-macOS.zip` from the release assets.
2. Verify its SHA-256 value against `CodexBoard-v0.1.1-SHA256SUMS.txt`.
3. Extract the archive and move `CodexBoard.app` to `/Applications` if desired.
4. Because this preview is ad-hoc signed and not notarized, macOS may block a
   normal first launch. Build from source if you do not explicitly trust the
   preview artifact.

## Requirements

- macOS 14 or later on Apple silicon.
- A local Codex CLI or trusted Codex application, already signed in.

## Trust boundary

This preview is **not** Developer ID signed or Apple notarized. It is intended
for local evaluation by people who can inspect or build the source. A future
public release must use a stable production bundle identifier, hardened
runtime, Developer ID signing, notarization, stapling, and Gatekeeper
verification.
